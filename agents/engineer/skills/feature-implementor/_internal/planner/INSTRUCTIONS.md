# Planning a Change

Use a brief plan to connect the requested result to the work and verification.
For a small change, a few sentences in the task are sufficient. For a longer
change, keep a durable plan near the project's current design records.

Useful planning details are the expected behavior, affected files or components,
implementation order, dependencies, compatibility, and commands that establish
success. Estimate the size of the diff when it helps constrain scope. Identify
material uncertainty and the evidence or decision that will resolve it.

Proceed within the user's authorization. Update the plan when implementation
evidence changes the approach. Use parallel work for independent tasks when it
helps, while keeping integration and final review with the responsible assistant.
