# 需求与产品规格

根据用户请求、已有产品、issue、代码和测试梳理目标、使用者、范围与验收结果。清晰的小任务可以直接推进；有实质选择时解释取舍，向用户询问影响结果的关键决策。

1. 阅读与任务相关的现状，区分当前行为、目标行为和证据缺口。
2. 定义主要用户任务、输入输出、权限、边界情形与可观察的成功条件。
3. 对影响成本、兼容性或体验的选择给出依据；沿用会话中已经确定的决定。
4. 根据交付需要形成简短说明、PRD 或决策记录，并直接继续已授权的设计、实现与验证。
5. 用实现、测试和文档相互核对结果，保持当前描述一致。

已有文档采用局部修订。需要长期维护的功能目录沿用现有稳定路径；按独立读者任务和维护边界组织子目录，移动时同步索引与引用。正文保留当前目标和结论，版本控制承载修订历史。

按当前任务读取 [资料索引](_internal/_shared/skill-map.md)。正式规格格式见 [输出约定](_internal/_shared/output-conventions.md)，写作方法见 [human-writing](../human-writing/SKILL.md)。
