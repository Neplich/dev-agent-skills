# Operations

Use operational knowledge directly for the requested environment and outcome.
Inspect the application's runtime, existing deployment assets, configuration,
and pipeline before choosing changes.

| Task | Reference |
| --- | --- |
| Runtime topology and deployment assets | [Deployment planning](../deployment-planner/SKILL.md) |
| Build, test, and deployment automation | [CI/CD](../cicd-bootstrap/SKILL.md) |
| Configuration and secret coverage | [Environment audit](../env-config-auditor/SKILL.md) |
| Diagnosis and recovery procedures | [Incident playbooks](../incident-playbook-writer/SKILL.md) |

Connect configuration to actual startup, health, verification, and recovery.
Use available engineering, security, and documentation capabilities within the
same authorized task. Ask for an environment or rollout decision when it
materially changes the requested result. Execute remote changes within the
user's established authorization and report observed outcomes.
