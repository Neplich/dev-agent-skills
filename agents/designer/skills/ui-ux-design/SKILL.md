# UI and UX Design

Identify the audience, primary task, content, and constraints from the request,
existing interface, and relevant project evidence. Inspect supplied references
and distinguish useful interaction patterns from incidental visual treatment.

## Shape the experience

1. Map the user's entry point, main action, success state, alternate branches,
   and recovery paths.
2. Organize pages, navigation, information hierarchy, and content around those
   tasks. Keep primary actions and current location easy to recognize.
3. Sketch layouts or prototypes at the level needed to decide structure. For
   implementation work, apply the design directly in the existing stack.
4. Define shared components and meaningful states: loading, empty, populated,
   validation error, permission-limited, disabled, and success.
5. Specify form behavior, feedback, keyboard access, focus movement, and
   responsive priorities. Check content at the project's important viewport sizes.
6. Review a representative end-to-end journey in the actual artifact where
   available, then refine friction, readability, and consistency.

A design document can include a journey, page inventory, layouts, components,
interaction rules, and responsive behavior. Choose sections useful to its
readers and place it with the project's existing design materials. For a
working UI, report what changed and which journeys and viewports were checked.
