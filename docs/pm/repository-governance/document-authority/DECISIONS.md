# 仓库文档权威与生命周期治理决策记录

## 已接受决策（Accepted）

| ID | 决策 | 理由与后果 |
| --- | --- | --- |
| D-001 | 本请求分类为 `existing_update`、`change_tier: major`，功能路径固定为 `repository-governance/document-authority`。 | 变更覆盖跨角色文档契约、Skill 指令组织、归档生命周期和仓库检查，属于仓库治理的二级功能，不改变单一 Agent 产品能力。 |
| D-002 | 当前复核确认的 14 份已完成活跃实施计划全部进入冻结归档，不删除。 | Issue #285 扫描识别了 13 份 `Implemented` 计划；#117 已关闭且 PR #128 已合并，证明 `docs-agent` 父计划的 `Draft` 是状态漂移，因此同规则纳入第 14 份。活跃入口应只表示尚未完成的工作。 |
| D-003 | 不新建中央 `docs/decisions/`；PM 产品决策继续保存在对应 feature-path 的 `DECISIONS.md`，Engineer 技术取舍保存在 TRD 或 ADR。 | 决策必须靠近其功能 owner，产品理由与技术理由需要分离；中央目录会制造第二套索引与归属判断。 |
| D-004 | 跨插件 handoff、closeout、Security escalation 和文档消费协议采用单一权威源；发布或安装时生成插件内只读副本，并执行 freshness check。 | Claude 与 Codex 的安装边界要求消费方能在本地读取必要协议，但多份人工维护副本会持续漂移；派生副本兼顾可读性与唯一权威。 |
| D-005 | QA E2E 的账号引用、测试用例、脚本片段和报告模板由 QA Skill reference 唯一拥有。 | 这些内容属于 QA 执行资产契约；PM PRD 只保留产品要求和验收，其他位置只引用而不复制模板。 |
| D-006 | Role Router 只保留入口凭据、路由表、阻塞条件和 Specialist 指针；精确行数、字数或命题预算由 Engineer TRD 确定。 | Router 的产品职责是可靠入口与分流，不应复制 Specialist 执行协议；机器预算属于实现与检查设计，不能在产品决策中提前锁定。 |
| D-007 | 不为 Design、QA、DevOps、Security 创建没有真实交付物的空文档镜像。 | 目录对称本身不产生产品价值，空镜像会增加无 owner 的结构和后续维护义务。 |
| D-008 | 五份超过 500 行的活跃文档必须先按章节所有权审查，再决定保留、收窄或拆分。 | 行数是审查信号，不是所有权结论；机械拆分可能把产品要求、技术设计或 QA 契约移动到错误 owner。 |
| D-009 | 本治理不改变七个 Agent 的用户可见职责、可用能力、名称或既有行为。 | Issue #285 的目标是减少权威文档面和重复规则，而不是修改产品功能；任何行为差异都需要重新进入产品范围确认。 |

## 决策后果

| ID | 后果 |
| --- | --- |
| C-001 | 日常文档加载面与人工同步面缩小，但冻结归档使仓库总行数下降有限。 |
| C-002 | 共享契约的源文件变更必须同步刷新派生副本；freshness 不通过时不得完成交付。 |
| C-003 | 实施阶段必须提供 14 份计划的精确归档映射、5 份超长文档的章节映射和受影响引用清单。 |
| C-004 | Router 的具体机器预算、派生副本生成方式与检查实现留给 Engineer TRD，不得反向改变产品边界。 |
| C-005 | 如果某受支持安装方式无法可靠消费派生副本，该阶段必须停止或回滚，不能恢复为多份人工维护权威。 |

## 已排除方案

| ID | 方案 | 排除理由 |
| --- | --- | --- |
| R-001 | 提取决策后删除已完成计划。 | 用户选择保留冻结历史；删除虽可由 Git 恢复，但会降低当前仓库内的直接审计能力。 |
| R-002 | 按内容价值分类，一部分归档、一部分删除。 | 需要逐份重新判断历史价值，且不满足用户已确认的全部冻结归档策略。 |
| R-003 | 新建中央 `docs/decisions/` 管理所有决策。 | 会远离 feature owner，并混合产品与技术决策。 |
| R-004 | 各插件继续人工维护共享契约副本。 | 无法消除漂移和多权威问题。 |
| R-005 | 只直接引用仓库内一个共享文件，不生成插件内副本。 | 不能保证所有 Claude 与 Codex 分发边界下都能读取跨插件文件。 |
| R-006 | 为四个缺失角色过程文档根创建空镜像。 | 结构对称不能证明真实交付需求，只会新增空维护面。 |
| R-007 | 用固定行数直接决定 Router 和超长文档内容去留。 | 行数不能替代职责与所有权判断；精确机器预算应由技术设计验证。 |
